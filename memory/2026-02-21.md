
## 2026-02-21 — SD/log wear-reduction changes applied

Context: Discord session with Max. Goal was to reduce SD-card wear in a soft/safe way.

### Changes applied

1) Journal cleanup (one-time)
- Commands run:
  - `journalctl --rotate`
  - `journalctl --vacuum-size=100M`
- Result:
  - cvlc log spam entries removed (from ~1,129,722 to 0)
  - journal size reduced to ~52.3M (freed ~805.3M)

2) Journald soft limits/tuning (persistent)
- File created:
  - `/etc/systemd/journald.conf.d/99-sd-card-softening.conf`
- Contents:
  - `[Journal]`
  - `SystemMaxUse=100M`
  - `SystemKeepFree=200M`
  - `SystemMaxFileSize=25M`
  - `MaxRetentionSec=14day`
  - `SyncIntervalSec=5m`
  - `RateLimitIntervalSec=30s`
  - `RateLimitBurst=200`
- Service action:
  - `systemctl restart systemd-journald`
- Verification:
  - service active
  - config visible via `systemd-analyze cat-config systemd/journald.conf`

### Explicitly NOT changed
- `/var/log` was NOT moved to RAM/tmpfs (user asked to keep this as-is).
- zram/noatime were discussed but not applied in this step.

### Rollback instructions

- Remove the applied journald drop-in and restart journald:
  - `sudo rm -f /etc/systemd/journald.conf.d/99-sd-card-softening.conf`
  - `sudo systemctl restart systemd-journald`

- Optional: verify effective config and size:
  - `systemd-analyze cat-config systemd/journald.conf`
  - `journalctl --disk-usage`

## 2026-02-21 — zram + swap tuning (RAM-first profile)

Applied on Raspberry Pi to reduce SD wear while keeping RAM safety margin.

### What was changed

1) Installed package:
- `zram-tools`

2) zram config (`/etc/default/zramswap`):
- `ALGO=lz4`
- `PERCENT=13`  (≈ 512 MiB zram on this host)

3) SD swap reduced (not removed):
- `/etc/dphys-swapfile`
- `CONF_SWAPSIZE=1024` (was 2048)

4) Kernel VM tuning:
- `/etc/sysctl.d/99-swappiness.conf`
- `vm.swappiness=10`

5) Services/actions:
- `systemctl restart dphys-swapfile`
- `systemctl enable --now zramswap.service`
- `systemctl restart zramswap.service`

### Result snapshot
- `/var/swap` ≈ 1.0 GiB
- `/dev/zram0` ≈ 505 MiB
- total swap ≈ 1.5 GiB
- `vm.swappiness = 10`

### Backups made
- Workspace backup of original dphys config:
  - `/home/pi4/.openclaw/workspace/.pi/backups/dphys-swapfile.before.2026-02-21-174707`
- System-side backup copy:
  - `/etc/dphys-swapfile.bak.2026-02-21-174707`

### Rollback (exact)

To restore previous behavior (no zram, 2G file swap):

```bash
sudo systemctl disable --now zramswap.service
sudo apt-get remove -y zram-tools
sudo cp -a /home/pi4/.openclaw/workspace/.pi/backups/dphys-swapfile.before.2026-02-21-174707 /etc/dphys-swapfile
sudo rm -f /etc/sysctl.d/99-swappiness.conf
sudo /sbin/sysctl -w vm.swappiness=60
sudo systemctl restart dphys-swapfile
cat /proc/swaps
```

Expected after rollback: only `/var/swap` around 2G, no `/dev/zram0`.
